# Browser Observation 是只读、短命、能力显式的深 module

AI 录制将以 Browser Observation 作为页面事实的唯一 seam：它在同一观察周期同步产生干净教程截图、结构化可交互目标、临时决策截图、远程观察投影和观察收据，并由 CDP 与 chrome.scripting 两个真实 adapter 提供实现。完整观察和元素映射只在本地短暂存在，观察过程不得修改目标网页；模型只接收用户授权后的最小脱敏投影，元素引用只在一次观察内有效，执行前由观察 module 复验。选择这一形状是为了集中当前散落的 DOM 遍历、指纹、iframe/Shadow DOM 能力、截图对齐和隐私裁剪，同时避免把持久化、模型调用、风险策略或动作执行塞进同一个 module。

## Considered Options

- 继续使用截图、目标文字和坐标校准：改动小，但网站兼容性知识会继续分散，无法形成可靠的通用能力。
- 向网页 DOM 注入永久元素标识：实现直观，但会污染页面、可能触发布局或站点行为，也让标识生命周期难以审计。
- 一次性替换现有 Agent 链：能够更快删除旧代码，但会同时改变观察、模型协议、风控与执行，商业回归风险过高。

## Consequences

- 正式动作以观察元素引用为主，视觉坐标只能作为显式、需确认的降级路径。
- 两个 adapter 共享共同能力基线，但通过观察能力声明暴露差异，不承诺伪等价。
- 新链只在开发与测试中影子验证；达到验收门禁后切换正式路径，不在客户版本中长期双轨运行。
- 发布新能力前必须扩展 AI 数据共享文案和隐私政策，使其明确覆盖远程观察投影。
