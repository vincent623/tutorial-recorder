## 1. 产品环境

**名称：** Tutorial Recorder
**标语：** 一个让人或 AI 都能录制操作教程的环境
**版本：** 2.0.1（规约状态已同步至 AI 驱动录制 MVP）

**环境描述：**
Tutorial Recorder 是一个 Chrome 扩展，为教程作者提供两种互补的操作录制环境——人工手动操作和 AI 自动操作。无论谁在"点"，最终产出相同结构的教程包（Markdown + PDF + 截图 + 音视频）。环境同时支持录制后的精细编辑，确保教程质量不取决于录制过程的完美程度。

**主要智能体：**
- 录制者（人类）：手动操作浏览器、配置参数、编辑教程、输入教程目标让 AI 执行
- 视觉分析 AI：单轮截图描述，为每一步生成中文说明
- 操作 AI（Agent）：多轮浏览器操控，根据用户描述自动完成操作并录制
- 教程读者（人类）：接收并使用教程包复现操作

**核心可供性：**
1. **录制可供性**（主要）：支持人工操作录制和 AI 驱动录制两种行动模式
2. **观察可供性**（主要）：自动采集截图、交互行为、音视频
3. **精化可供性**（次要）：录制后编辑每一步的截图、说明和顺序
4. **导出可供性**（主要）：生成可分享的教程 ZIP 包
5. **配置可供性**（辅助）：连接 AI Provider、定制提示词、设置导出偏好

## 2. MAS：最小可供故事

### MAS-1：边操作边录制教程（已实现）

**故事主题：**
录制者在浏览器中完成一系列操作，环境自动将操作过程转化为结构化教程，无需任何后期编辑即可分享。

**核心可供性序列：**
1. **启动可供性**：点击"开始录制"按钮（感知：Popup 中的主操作按钮 + Badge 变为 REC）
2. **采集可供性**：环境自动定时截图 + 记录用户交互（感知：页面右上角截图反馈浮层 + 计数器递增）
3. **干预可供性**：手动截图 / 暂停 / 继续（感知：快捷键 Ctrl+Shift+S + 控制按钮）
4. **终止可供性**：点击"停止录制"（感知：Badge 变为处理中 + 进度提示）
5. **输出可供性**：自动生成 ZIP 下载（感知：下载完成通知 + 历史记录出现新条目）

**意义闭合：**
操作者的即兴操作被环境自动捕获、结构化、描述，转化为可复现的教程。操作的临时性转化为教程的持久性。

**内在动机：**
- 兴趣：看到自己的操作被自动转化为教程，有创造感
- 精通：逐渐掌握何时截图、何时暂停的节奏
- 自主：可以选择手动或自动截图、调整间隔、选择是否启用 AI

**故事依赖：** 无（基础故事）

**已实现状态：** MAS-1 在 v1.3.0 中已完整实现。

---

### MAS-2：录制后精修教程（已实现）

**故事主题：**
录制者打开工作台，逐步审视 AI 生成的说明和截图，修正不准确之处，调整步骤顺序，替换不理想的截图，直到教程质量满足要求。

**核心可供性序列：**
1. **回溯可供性**：在工作台中打开历史录制（感知：历史列表 + 时间/截图数/时长元信息）
2. **审阅可供性**：逐步查看截图和说明（感知：步骤卡片列表 + 原图预览弹窗）
3. **修改可供性**：编辑步骤说明文字（感知：可编辑文本框 + 实时脏检测提示）
4. **重排可供性**：拖拽或上下移动步骤（感知：拖拽手柄 + 移动按钮 + 视觉位置变化）
5. **增删可供性**：插入新截图 / 替换截图 / 删除步骤（感知：操作按钮 + 确认对话框）
6. **重导可供性**：保存修改并重新导出 ZIP（感知：保存按钮状态变化 + 导出完成提示）

**意义闭合：**
不完美的录制过程不再意味着不完美的教程。录制者可以从容地"先录下来再说"，再通过精修让教程达到发布质量。

**内在动机：**
- 兴趣：逐帧审视自己的操作过程，发现之前没注意到的细节
- 精通：通过编辑理解"好教程"的结构，提升下次录制的质量
- 自主：完全掌控每一步的内容和呈现

**故事依赖：** 需要 MAS-1（必须先有录制才能精修）

**已实现状态：** MAS-2 在 v1.3.0 中已完整实现。

---

### MAS-3：AI 看懂操作并描述（已实现）

**故事主题：**
视觉分析 AI 审视每一步截图，结合页面标题、URL 和用户交互记录，生成一句精准的中文操作说明——描述"用户正在做什么"而非"页面长什么样"。

**核心可供性序列：**
1. **配置可供性**：在设置页选择 Provider、填入 API Key、选择模型（感知：Provider 下拉 + 密码输入框 + 模型 ID 字段）
2. **模板可供性**：选择或自定义提示词版本（感知：提示词预设下拉 + 模板编辑器 + 占位符提示）
3. **分析可供性**：录制停止后，AI 逐图分析并生成步骤说明（感知：步骤 N/M 进度提示 + 超时自动降级）
4. **降级可供性**：AI 不可用时回退到基于交互记录的默认说明（感知：进度提示"未配置 AI，使用默认说明"）

**意义闭合：**
录制者不需要自己写每一步说明。AI 将截图和上下文转化为人类可读的操作描述，让教程制作的体力活减少到最低。

**内在动机：**
- 兴趣：观察 AI 如何理解自己的操作，有时会发现意想不到的准确描述
- 精通：通过调整提示词模板，逐步学会引导 AI 产出更精准的描述
- 自主：完全可以选择不用 AI，手动写说明

**故事依赖：** 需要 MAS-1（分析 AI 作用于录制产物）

**已实现状态：** MAS-3 在 v1.3.0 中已完整实现。

---

### MAS-4：告诉 AI 你要什么教程（v2.0.0 已实现 — Phase 3）

**故事主题：**
录制者用一句话描述想要的教程，操作 AI 自动在浏览器中执行操作，每一步自动截图并生成说明。录制者可以旁观、随时接管、或让 AI 独立完成。

**核心可供性序列：**
1. **委托可供性**：在 Popup 中输入教程目标（如"在飞书上创建一个多维表格"）（感知：文本输入框 + "AI 录制"按钮 + 调试状态提示）
2. **执行可供性**：AI 通过 CDP 控制浏览器执行操作，每步自动截图（感知：实时步骤列表更新 + Badge 显示 AI 录制状态）
3. **接管可供性**：录制者随时点击"接管操作"切换到手动模式（感知：接管按钮 + 模式切换状态提示）
4. **干预可供性**：AI 执行中录制者可点击"暂停 AI"（感知：暂停按钮 + AI 等待状态）
5. **终止可供性**：AI 完成任务 / 达到步数上限 / 录制者手动停止（感知：完成通知或限制提示）
6. **审查可供性**：与 MAS-2 相同，在工作台中审阅和精修 AI 录制的教程

**意义闭合：**
录制者从"操作者"变为"导演"——只需要知道想要什么教程，不需要自己一步步操作。AI 和人类可以交替完成同一条教程的不同部分，最终的产物不受过程影响。

**内在动机：**
- 兴趣：观察 AI 如何理解和执行自己的意图，像看自动化表演
- 精通：学会写出更精确的教程目标描述，引导 AI 更准确执行
- 自主：随时可以接管，始终保持对操作的控制权

**故事依赖：**
- 需要 MAS-1（复用截图、导出机制）
- 需要 MAS-3（复用 AI 分析能力为每步生成说明）
- 需要 CDP 截图增强（Phase 1）

**实现状态：** v2.2.0 已实现 AI 录制加固：Popup 目标输入、AI 录制按钮、CDP Agent 循环、`click_at_xy` / `type_text` / `scroll` / `finish` 工具、暂停/继续、接管、可配置步数和超时、单轮决策失败重试 1 次、动作后页面稳定/异常检测、失败后保留步骤并允许接管或停止导出。

**后续加固：** 可继续补充真实 AI 自动录制 E2E 样例和更细粒度的页面语义校验。

### MAS-5：CDP 精确感知（v1.4.0 已实现 — Phase 1）

**故事主题：**
通过 Chrome DevTools Protocol，环境获得超越肉眼截图的感知能力——后台截图、区域裁切、精确元素定位，让录制质量不再受限于前台可见性。

**核心可供性序列：**
1. **后台截图可供性**：标签页被遮挡时仍可截图（感知：截图计数继续增加，不因切换标签而中断）
2. **区域裁切可供性**：录制时选择只录制页面的某个区域（感知：区域选择框 + 裁切后的截图预览）
3. **元素定位可供性**：精确捕获用户点击了哪个元素（感知：步骤说明中出现精确的按钮名、输入框名，而非模糊的"页面元素"）
4. **坐标标注可供性**：获取元素精确像素坐标，为截图批注提供位置基础（感知：步骤详情中显示元素高亮框）

**意义闭合：**
录制的精度从"截了一张屏"提升到"精确知道用户在哪里做了什么"。这是后续截图批注和 AI 驱动录制的感知基础。

**内在动机：**
- 兴趣：看到步骤说明从模糊变精准，AI 描述质量的提升可感知
- 精通：理解 CDP 能力边界，知道什么场景下元素追踪最可靠
- 自主：可以选择使用传统截图或 CDP 截图模式

**故事依赖：** 需要 MAS-1（增强其截图和交互追踪能力）

**实现状态：** v1.4.0 已实现 CDP 截图引擎、`chrome.debugger` 生命周期、后台截图、裁切参数、CDP 附加失败回退、点击坐标采集、`DOM.getNodeForLocation` / `DOM.describeNode` 元素定位和 Popup 调试状态提示。

**后续加固：** 裁切区域目前是数值配置，尚未提供拖拽区域选择框；步骤详情尚未显示元素高亮框。

---

### MAS-6：AI 实时建议步骤描述（v1.5.0 已实现 — Phase 2）

**故事主题：**
录制过程中，AI 实时审视刚截取的截图，立即生成建议的步骤说明。录制者可以看到 AI 的理解是否准确，在录制过程中就决定是否需要重新操作。

**核心可供性序列：**
1. **实时分析可供性**：每次截图后立即触发 AI 分析（感知：Popup 中当前步骤建议说明实时出现）
2. **纠正可供性**：录制者对 AI 建议不满意时手动输入替代说明（感知：可编辑的建议文本框）
3. **反馈可供性**：手动纠正后的说明作为下一轮 AI 的参考上下文（感知：后续步骤的 AI 描述更贴近用户风格）

**意义闭合：**
教程质量把控从事后提前到录制过程中。录制者不再需要"录完再看 AI 说了什么"，而是边录边看，及时调整。

**内在动机：**
- 兴趣：实时看到 AI 对自己操作的解读，形成人机协作感
- 精通：通过即时反馈学习如何操作能让 AI 更准确地理解
- 自主：可以忽略 AI 建议，全部自己写

**故事依赖：**
- 需要 MAS-1（复用截图流程）
- 需要 MAS-3（复用 AI 分析能力）
- 需要 MAS-5（CDP 增强的元素定位让 AI 描述更精准）

**实现状态：** v1.5.0 已实现实时建议开关、截图后异步 AI 分析、latest-only 队列、Popup 最新建议面板、编辑覆盖和最终导出优先使用用户修正文案。

## 4. 环境约束

### 4.1 物理约束

| 约束 | 对可供性的影响 |
|------|--------------|
| Chrome Manifest V3 无持久后台 | service worker 可能随时休眠，录制状态必须持久化到 chrome.storage.session |
| Offscreen Document 生命周期限制 | 媒体录制和 PDF 生成依赖 offscreen document，必须在 activity 间隙保持存活 |
| Popup 窗口尺寸固定且狭小 | Popup 中只放录制控制和快速设置，完整 UI 放独立工作台标签页 |
| IndexedDB 存储空间有限 | v2.1.0 已将截图/音视频 payload 拆入 `assets` store，仍需要存储用量提示和清理机制 |

### 4.2 结构约束

| 约束 | 对可供性的影响 |
|------|--------------|
| 录制会话与浏览器标签页绑定 | 关闭目标标签页将导致截图失败，需要检测并通知用户 |
| AI 调用为单请求阻塞式 | 步骤分析串行执行，N 步教程的 AI 处理时间为 N × 单步耗时 |
| chrome.debugger 会附加调试提示条 | AI 录制模式会触发黄色警告条，需要在 UI 中提前告知用户 |

### 4.3 安全约束（来自 real.md）

| 约束 | 可供性限制 |
|------|-----------|
| API Key 仅存 chrome.storage | AI 配置不可导出、不在历史记录中可见、不出现在日志中 |
| chrome.debugger 录制结束即 detach | AI 录制停止后必须立即解除调试附加，不得后台驻留 |
| 截图含隐私不得自动上传 | 导出 ZIP 仅下载到本地，任何分享功能必须用户主动确认 |
| AI Agent 步数/超时上限 | 单次 AI 录制默认最多 50 步、10 分钟，到达上限后优雅停止 |

## 5. 感知通道

### 5.1 视觉可供性（人类）

| 元素 | 感知到的操作 | 设计模式 |
|------|------------|---------|
| 主操作按钮"开始录制" | 可点击启动录制 | 大号蓝色按钮，disabled 时灰显 |
| Badge 文字 REC / II / ... | 可感知录制状态 | 红色 REC 录制中，黄色 II 暂停，蓝色...处理中 |
| 页面右上角截图反馈浮层 | 可感知截图动作已触发 | 蓝色浮层"已截图 (N)"，1.8s 后淡出 |
| 截图计数器 + 录制时长 | 可感知录制进度 | 实时递增的数字 |
| 步骤卡片列表 | 可感知教程结构 | 缩略图 + 说明文本 + 操作按钮 |
| AI 录制输入框 | 可输入教程目标 | 带占位符的文本框 + "AI 录制"按钮 |
| 调试状态提示横幅 | 可感知 CDP 调试附加状态 | 黄色横幅"录制中，Chrome 可能显示调试提示" |

### 5.2 语义可供性（AI — 操作 Agent）

| 元素 | 语义标记 | 感知到的操作 |
|------|---------|------------|
| CDP Screenshot 返回 | Page.captureScreenshot response | 可获取当前页面视觉状态 |
| CDP DOM 节点 | DOM.getNodeForLocation result | 可定位点击坐标对应的元素 |
| CDP 输入事件 | Input.dispatchMouseEvent | 可在指定坐标执行点击 |
| CDP 文本输入 | Input.insertText | 可在焦点元素中输入文字 |
| CDP 滚动 | Input.dispatchMouseEvent(mouseWheel) | 可滚动页面查看更多内容 |
| function calling 工具定义 | tools 数组中的 click/type/scroll/finish | 可决定下一步执行什么动作 |

### 5.3 跨模态可供性

| 可供性 | 人类通道 | AI 通道 | 统一操作 |
|--------|---------|--------|---------|
| 截图 | chrome.tabs.captureVisibleTab | CDP Page.captureScreenshot | 获取页面视觉快照 |
| 点击操作 | 物理鼠标点击 | CDP Input.dispatchMouseEvent | 在指定位置触发点击 |
| 文本输入 | 键盘输入 | CDP Input.insertText | 向焦点元素输入文字 |
| 步骤说明 | 手动编辑文本框 | 视觉分析 AI 生成 | 为截图创建描述文字 |
| 教程导出 | 点击"导出 ZIP"按钮 | 同（AI 录制结束后自动触发） | 生成教程包 |

## 6. 反馈机制

### 6.1 即时反馈（< 100ms）

| 操作 | 人类反馈 | AI 反馈 |
|------|---------|--------|
| 点击"开始录制" | 按钮状态切换 + Badge 变 REC | — |

| 编辑步骤说明 | 文本框值更新 + 状态提示"已修改" | — |
| CDP 点击执行 | 页面真实响应 | CDP 返回值确认 |

### 6.2 进度反馈（< 1s）

| 操作 | 人类反馈 | AI 反馈 |
|------|---------|--------|
| AI 步骤分析中 | "正在分析步骤 N/M..." 状态提示 | — |

### 6.3 完成反馈（< 5s）

| 操作 | 人类反馈 | AI 反馈 |
|------|---------|--------|

| AI 录制完成 | "AI 录制完成，共 N 步" + 历史记录出现 | Agent 循环结束 + debugger detach |
| AI 录制达到上限 | "已达到最大步数/时间限制，可继续编辑后导出" | Agent 循环终止 |

## 8. 非可供性（明确禁止的动作）

| 禁止动作 | 理由 |
|---------|------|
| 自动上传教程到任何云服务 | real.md 约束：截图含隐私，不得自动上传 |
| 在非录制状态下保持 debugger 附加 | real.md 约束：录制结束即 detach |
| 让 AI 在用户未确认的情况下操作支付/删除等危险动作 | 安全原则：AI 操作应有动作白名单或确认机制 |
| 存储用户 API Key 到 IndexedDB 或日志 | real.md 约束：Key 仅存 chrome.storage |
| 限制只能使用一家 AI Provider | 产品定位：开放接入，用户选自己的 Key |
| 要求用户注册账号 | 产品定位：本地工具，无需账号体系 |

## 9. 实现路线

### Phase 1 — CDP 截图增强（MAS-5，v1.4.0 已完成）

**目标：** 用 chrome.debugger CDP 增强现有截图和交互追踪能力。

**涉及可供性：** A16（后台截图）、A17（元素定位）、A24（区域裁切）、A25（坐标标注）

**改动范围：**
- background.js：新增 CDP 截图路径（chrome.debugger.attach + Page.captureScreenshot）
- background.js：新增元素定位路径（DOM.getNodeForLocation）
- content.js：增强交互采集，利用 CDP 坐标精确化 target 描述
- manifest.json：新增 `debugger` 权限
- popup.js / settings.js：新增 CDP 截图模式开关、区域裁切 UI、调试状态提示

### Phase 2 — AI 实时建议（MAS-6，v1.5.0 已完成）

**目标：** 录制过程中每次截图后立即触发 AI 分析，将建议显示在 Popup 中。

**涉及可供性：** A15（AI 实时建议）

**改动范围：**
- background.js：截图回调中增加异步 AI 分析调用
- popup.js：新增实时建议展示区域，支持编辑覆盖

### Phase 3 — AI 驱动录制（MAS-4，v2.0.0 已完成 MVP）

**目标：** 用户输入教程目标，操作 AI 通过 CDP 自动执行浏览器操作，每步截图 + 生成说明。

**涉及可供性：** A08（AI 录制委托）、A09（接管操作）、A18（AI 暂停/继续）

**改动范围：**
- background.js：新增 AI Agent 循环（截图 → AI 决策 → CDP 执行 → 记录 → 循环）
- background.js：新增 AI Agent 运行时状态管理
- background.js：定义 AI tool schema（click_at_xy、type_text、scroll、finish）
- popup.js：新增 AI 录制入口（目标输入框 + AI 录制按钮 + 接管按钮）
- popup.js：实时展示 AI 执行进度（步骤列表 + 当前状态）
- manifest.json：确认 `debugger` 权限
